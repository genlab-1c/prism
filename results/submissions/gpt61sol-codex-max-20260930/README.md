# GPT-6.1 Sol в PRISM

Проверено 30 сентября 2026 года. Модель текущего Codex-сеанса: `gpt-6.1-sol`, reasoning effort: `max` (подтверждено локальными метаданными turn_context).

| Этап | Полностью решено | Пройдено тестов | Измерено осей SMOP |
|---|---:|---:|---:|
| Первая попытка | 32/35 | 166/174 | 84/125 |
| После исправления трёх решений | 35/35 | 174/174 | 85/125 |

Для каждой задачи сохранена одна первая генерация. Для испытания модели основной результат — первая попытка: 32/35 задач (91,4%), 166/174 тестов (95,4%). Исправленные решения показывают результат агента после обратной связи; их следует публиковать отдельным этапом.

Решения всех 35 задач были сохранены и зафиксированы SHA-256 до получения результатов скрытых тестов. До написания решений агент прочитал условия task.yaml и схемы config_spec.yaml. Эталонные решения и исходники скрытых тестов агенту не показывались. Затем штатный проверяющий код PRISM исполнил скрытые проверки. Позднее дополнительный self-check читает эталоны внутри процесса проверки и выводит только статусы.

Этот запуск использует одну общую беседу Codex и доступные агенту инструменты. Он отличается от стандартного generate через API и требует отдельного обозначения в публикации. Нельзя заменять им стандартную строку GPT-6.1 Sol в лидерборде без согласования условий с мейнтейнером.

Измерены S и M для обеих категорий, O для корректных решений категории A. Для B оптимальность и доказательство обращений к данным по SDBL не измерены: O и P записаны как null. Полный рейтинг SMOP и сравнение со строками с полным охватом не установлены. Значение Q=10 после исправлений относится только к измеренным осям.

API temperature, seed, лимит ответа, фактические токены и цена этого сеанса недоступны. Нули в этих полях экспериментальных JSON — обязательные значения по умолчанию схемы PRISM, их нельзя интерпретировать как измеренные нулевые расходы. provenance.json и agent_provenance явно фиксируют отсутствие измерения.

PRISM 1.10.0; исходный commit: `aef115465d42d9863bcae675e612218fc66e6a8d`. Условия, тесты и правила метрики в исходном репозитории сохранены. Compat hash: `81a97669b66f7318e1fe0ea7a5f2423cc38a704401b1b7573868b1a9157e98e2`.

Среда: Windows, Python 3.12.14, OneScript 2.0.1 для Windows, BSL LS 0.29.0, Java JBR 25.0.3, 1С 8.3.27.2214. Windows-адаптер запускает собственные решения локально и использует штатные скореры. На OneScript есть сторож по настенному времени, квота процессорного времени Linux не воспроизводится. Для каждой задачи B создана отдельная синтетическая файловая база внутри work; рабочие базы не используются.

Ошибки первых попыток:

- A5: Структура.Свойство при отсутствующем ключе заменяло счетчик на Неопределено; исправлена инициализация счетчика.
- B17: агрегирование запроса приводило к взаимозачету долга и авансов; исправлен выбор остатков с сохранением измерения Договор и последующее суммирование положительных остатков.
- B19: платформа запрещает В ИЕРАРХИИ внутри агрегатной функции; отбор перенесен в WHERE двух ветвей дебета и кредита.

32 решения после первого прогона сохранены без изменений; повторно проверены только A5, B17 и B19. Первые попытки в first_attempt неизменны.

Проверки среды:

- Тесты проекта: 468 passed, 23 skipped. Это отдельный результат от 174 тестов решений.
- Штатный prism check: контракты и банк задач согласованы; в исходном Windows-режиме исполняемые срезы пропущены из-за путей Linux/Docker. Дополнительная проверка подтвердила функциональную корректность всех 35 эталонов и 14 из 15 нагрузочных пар эталон/baseline категории A. Медленный якорь A9 остановлен сторожем на n=16000: его O не измерен, поэтому полный prism check в этом Windows-режиме не зелёный. Нагрузочные якоря B не проверялись. Подробности находятся в summary.json, evidence/check-windows.json и evidence/check-canonical-B.json.

Все четыре пакета submission созданы штатным harness.submit.build_submission и прошли verify_submission с совпадением отпечатка текущего бенчмарка. Это проверка версии, она не означает равенства протокола агентного запуска и стандартного API-прогона.

В этом каталоге размещены четыре пакета submission: категории A и B для первой попытки и отдельно для решений после обратной связи. Основной результат испытания модели — первая попытка. Архив GPT-6.1-Sol-PRISM-2026-09-30.zip содержит исходные решения, исправления, оценки, логи, Windows-адаптер и SHA-256 манифест. Архив был собран до публикации; его внутренний отчет описывает состояние на момент упаковки. SHA-256 архива: `9115255a11469143a7a701656f36dab0e62934bfc0336b1dad543be5485f1a40`. Порядок приема описан в [CONTRIBUTING.md](https://github.com/genlab-1c/prism/blob/main/CONTRIBUTING.md).

Для воспроизведения на Windows: uv sync; установить OneScript 2.0.1 и BSL LS 0.29.0 в tools; обеспечить Java 21+ и 1С 8.3.27.2214. Указанные в windows_adapter.py пути настроить под свою установку. Подготовить пустую синтетическую конфигурацию через prepare_onec.py, затем score_initial.py A и score_initial.py B; score_repairs.py проверяет три исправления. Для проверки среды сначала выполнить check_canonical_b.py, затем check_windows.py. Freeze_initial.py повторно запускать нельзя: он защищен от перезаписи первых попыток.
